# Spatial receipt revalidation and admission extension

The strengthened checker accepts the retained calibration and matrix, plus one
new matrix boot with five added store-admission controls. All matrix runs have
30 native observations: 22 permits and eight bounds rejections. The original
admission profile has five loads (two accepted, three rejected); the new profile
has ten loads/stores (four accepted, six rejected). No BPF program executes.

receipt as having been generated by the corrected checker.

## Scope of the stronger checks

Every capability base must equal the production provider's selected address;
every cursor must equal that address plus the case offset. Recorded PCs must
identify the exact byte/halfword load/store within the complete 36-word linked
helper. The four forms require scalar `w8`, capability `c2`, zero displacement
and the preceding full-capability operand capture; fault PC/word must agree.
The linked words are checked against the retained helper bytes and range
identities. These are fixed-form checks, not a general native validator.

Only zero relocation is supported: retained boots report KASLR disabled for
lack of seed; new boots require explicit `nokaslr` with matching command/kernel
observations. A consistent EFI message is allowed. Missing, unknown or
contradictory placement evidence fails.

The launcher now requires a rechecked saved PASS calibration for the same
image, configuration and overlays before a matrix boot. Calibration demonstrates
one valid load and recovery from one expected bounds fault, not rejection of
unrelated kernel faults. Both current receipt checkers require actual kernel
powerdown, QEMU exit zero and absence of failure markers. The ownership
[completion recheck](../../ownership-native-trace/revalidation/receipt.json)
does not complete its pending native inspection.

## Offline reproduction

From the repository root:

```sh
make checker-tests
make evidence-recheck
make evidence
```

These targets need no Docker, QEMU or downloads and are included in `make check`.
The 16 host regression tests include constructed bad bases, PCs, operands,
syndromes, admission fixtures, shutdown records and calibration identities.
Constructed records test checker rejection, not runtime bypass or extra native
observations. `evidence-recheck` compares recalculated results to published
receipts; `evidence` checks the global publication hashes only.

The [publication manifest](../../../publication-manifest.json) distinguishes
original and publication identities. The unchanged original package remains
under `../build/`, `../run/`, `../calibration/` and `../derivation/`; these new
records do not overwrite it. Full kernels and tool distributions remain
external. This is selected-access synthetic validation through the production
provider, not admitted invalid BPF, an original CVE replay, complete mediation
or independent external reproduction.
